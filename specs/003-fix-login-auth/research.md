# Research: 登录授权验证修复

**Created**: 2026-06-01

## R1: 登录成功的统一判定

**Decision**: 所有登录入口统一产出候选凭证，并通过受保护的当前用户身份检查后才转换为有效登录状态。

**Rationale**:
- 当前 `boss login` 在获得 Cookie 后立即保存，用户信息获取失败被忽略，导致"登录成功"可能只是"拿到了若干 Cookie"。
- 规格要求 100% 的成功提示都对应已验证账号身份，因此验证失败、未知或服务不可用都不能保存新凭证。
- 当前项目已有 `ApiClient`、`RESUME_BASEINFO_URL` 和 `PROFILE_API`，适合作为验证候选；验证逻辑应返回账号身份摘要，而不是只返回 boolean。

**Alternatives considered**:
- 仅检查关键 Cookie 名称：无法证明服务端接受授权。
- 使用搜索/推荐接口验证：可能受频控、业务权限或安全策略影响，不适合作为登录身份的唯一判定。
- 继续允许用户信息获取失败但登录成功：直接违反规格的统一成功标准。

## R2: 候选凭证与持久化凭证分离

**Decision**: 引入候选凭证概念，登录方式只负责获取候选凭证；`saveCredential` 只接受已验证的登录结果或在保存前强制调用验证流程。

**Rationale**:
- 这能保证二维码、Web、浏览器提取三类实现不各自决定"成功"。
- 新登录失败时可以保留旧凭证，避免把空 Cookie、部分 Cookie 或未验证 Cookie 写入磁盘。
- 该设计支持后续在 `status` 和 `me` 中复用同一验证结果语义。

**Alternatives considered**:
- 在每个登录方式内部调用验证：会重复实现错误处理，且容易出现某条路径漏验。
- 保存后再验证，失败再删除：存在短暂污染持久化状态的窗口，多进程场景下风险更高。

## R3: 默认登录和指定浏览器的回退策略

**Decision**: 默认 `boss login` 可以自动检测可用本机会话；用户显式指定 `--browser` 时，只验证指定来源，失败时不静默切换到其他浏览器或登录方式。

**Rationale**:
- 默认登录的目标是最快完成可用登录，自动检测符合用户预期。
- 指定浏览器通常意味着用户在多账号或多配置文件环境中有明确选择，静默切换会造成错误账号登录。
- 失败提示应列出可选下一步，但实际切换由用户重新执行命令。

**Alternatives considered**:
- 指定浏览器失败后自动回退默认检测：可能使用错误账号，违反"尊重用户选择"。
- 默认登录失败后自动打开二维码或 Web：会改变用户交互模式，不利于脚本化使用。

## R4: Web 登录可行性边界

**Decision**: `--web` 必须验证浏览器登录结果是否能回收到 CLI；如果浏览器页面登录成功但 CLI 没有得到可验证凭证，应明确失败。

**Rationale**:
- 当前 Web 登录依赖本地回调读取 Cookie，但 BOSS直聘 登录页不一定支持通用 OAuth 风格 `redirect_uri`。
- 规格要求避免"浏览器已登录但 CLI 未登录"的模糊状态。
- 因此计划把 Web 登录定义为候选凭证获取方式：只有回调携带可用凭证并通过身份验证时才成功。

**Alternatives considered**:
- 打开网页后提示用户手动重跑默认登录：这可以作为错误提示下一步，但不能视为 `--web` 本次成功。
- 从浏览器进程或 DevTools 自动抽取网页登录 Cookie：实现复杂且可能引入重型依赖，不纳入本次范围。

## R5: 错误阶段和用户提示

**Decision**: 登录错误统一归类为 `credential_acquisition`、`awaiting_authorization`、`authorization_verification`、`credential_persistence`、`cancelled`、`timeout` 等阶段，并映射到中文提示和 JSON 错误码。

**Rationale**:
- 用户现在关心的是"完全授权验证不了"，必须知道失败是在拿凭证、等用户确认、验证授权还是保存凭证。
- 统一阶段方便 CLI human output、JSON mode 和测试断言一致。
- 提示可给出下一步命令，但不输出 Cookie、token 或完整敏感响应。

**Alternatives considered**:
- 直接抛出底层 Error message：消息不稳定，且可能泄露敏感信息或缺少下一步。
- 仅输出"登录失败"：不可操作，不满足 SC-003。

## R6: 测试边界

**Decision**: 以 mock 外部网络和文件系统边界为主，覆盖四种入口的成功、失败、取消和超时语义；真实 BOSS直聘 服务只保留手动 quickstart 验证。

**Rationale**:
- 登录服务、二维码扫码和浏览器回调依赖外部环境，自动化测试应可重复。
- 核心风险在状态转换、保存时机和错误语义，这些可通过单元测试稳定验证。
- CLI smoke 测试确保命令合同和 JSON envelope 不回归。

**Alternatives considered**:
- 自动化真实扫码/Web 登录：不可在 CI 中稳定运行。
- 只做手动测试：不足以防止保存未验证凭证的回归。
